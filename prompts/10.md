## 日记列表的拉取逻辑
在后端，日记按创建时间 created_at 排序，相应有一个列表索引值。假设索引值为 0,1,2,..., n-1.

在前端，指定三个变量：
+ index, 表示游标。在初次加载时，默认值为 n-1.
+ pre_number, 表示游标之前的数量
+ post_number, 表示游标之后的数量
前端会从后端拉取列表索引值对应于从 index - pre_number 到 index + post_number 区间的日记，作为 entries 列表，并渲染。

有两个边界情况：
1. index - pre_number <= 0, 即已拉取到最早一篇日记。此时在前端应渲染提示“没有更早的日记了”。当前前端在拉取到第一篇时已加入类似提示。
2. index + post_number >= n-1. 即日记已拉取到底部。此时在列表末尾添加一个“新建日记”区即可。

采取这种方式，可以避免在两种模式下切换可能引起的问题。但这可能需要对当前的前端、后端进行重新设计。
请你评估两个方案，并给出建议。
